The person behind the projects

Hi, I’m Steve.

My interest in business AI starts with a practical question: how can we use it to make work better?

Through this website, I share my thinking about AI strategy, enterprise workflows, governance and adoption, and productivity. I’m interested in the decisions that connect an idea to something useful: what to build, who it helps, how it should work and how to judge the result.

I also put those ideas into practice. This website and its AI Token Consumption & Cost Calculator are examples of what I have built together with ChatGPT.

My approach to Business AI

  • Start with the business need. Identify the task, the people involved and the improvement that would matter.
  • Make assumptions visible. Explain the inputs, limits and decisions behind a tool or recommendation.
  • Keep people accountable. AI can help produce an answer; someone still needs to review it and decide what happens next.
  • Build, test and refine. Try the result, ask what is unclear and improve the experience based on what you find.

01 / How I built this website with ChatGPT

Personal project · GitHub Pages · HTML, CSS and JavaScript

The problem I wanted to solve

I wanted a place to share Business AI insights with a consistent structure and a straightforward reading experience.

What I built

A website organised around four content pillars, with individual articles and an interactive resource. Longer pages use an anchored table of contents to help readers find what they need.

How I worked with ChatGPT

I described the intended result, reviewed the pages and asked for specific improvements. Those included making pillar pages visually consistent and adding section navigation to longer content.

A prompt you can adapt

Create a responsive HTML page for a business insights website. Use a light blue-and-white design, navy headings and clear navigation. Include a short introduction, topic cards and a footer. Use accessible HTML and put the CSS in the same file. Explain how to upload it to GitHub Pages. Ask me for my topic names and existing filenames before linking to other pages.

Build it yourself

You’ll need: a GitHub account, a text editor, a browser and access to ChatGPT. Account or plan availability may affect the tools you can use.

  1. Define your audience, main topics and the action you want visitors to take.
  2. Ask ChatGPT for a single self-contained page. Save it as index.html and open it in your browser.
  3. Review the wording, colours, links, keyboard navigation and mobile layout. Give specific feedback and request a complete updated file.
  4. Create a GitHub repository. Upload index.html, then open the repository’s Settings → Pages. For a simple HTML site, choose deployment from a branch and select the branch and folder containing your file.
  5. For setup details, see the official GitHub Pages publishing guide. Open the address shown by GitHub Pages once deployment finishes. Test the live page, not just the local copy.
  6. Add further pages using consistent navigation and filenames. Keep a copy of working files before replacing them.

What needed improving

Consistency mattered across the content pillars. Anchored contents menus made longer pages easier to explore. Clear filenames also mattered: an extra .html extension can create a separate file instead of updating the intended page.

Explore and adapt the code

To inspect a page, open its HTML file in the website’s GitHub repository. For a small starting point, you can also ask ChatGPT to generate a page using the example prompt above.

What I learned

A clear brief helps, but reviewing the actual experience is essential. The useful improvements often came from noticing something awkward and asking for a focused change.

02 / How I built the AI token calculator with ChatGPT

Personal project · Interactive HTML calculator · Illustrative pricing

The problem I wanted to solve

I wanted readers to explore how AI workflow volumes, calls, tokens and model prices affect a consumption estimate—and understand what that estimate leaves out.

What I built

A calculator with live monthly totals, annual projections, volume scenarios and currency labels. It includes governance guidance and an illustrative story about an Australian logistics CFO.

Open the calculatorDownload calculator HTML

How I worked with ChatGPT

I asked for editable assumptions and clearly hypothetical prices. I then refined the page by adding anchored navigation and the CFO example. When the infographic did not load, we embedded it in the HTML. We also reduced its displayed size so it was easier to follow.

A prompt you can adapt

Build a self-contained responsive HTML calculator for AI model token costs. Include monthly document volume, AI calls per document, average input and output tokens per call, and separate prices per million tokens. Show monthly and annual token costs, with optional volume scenarios. Use clearly hypothetical default prices and a currency label that does not convert exchange rates. Explain the exclusions, validate inputs, and keep all calculations in the browser. Use an anchored table of contents for longer content.

Build it yourself

  1. Download the HTML file above and keep a copy of the original.
  2. Open it in a browser. Change the usage assumptions and observe how the estimates respond.
  3. Open the file in a text editor, or give it to ChatGPT with a specific request to adapt the labels, design or workflow.
  4. Check the arithmetic independently. For 1,000 documents, three calls per document, 4,000 input tokens and 1,000 output tokens per call, monthly usage is 12 million input tokens and 3 million output tokens.
  5. At hypothetical prices of 2 per million input tokens and 8 per million output tokens, the monthly model token cost is 48 in the selected currency. Selecting a currency changes labels, not exchange rates.
  6. Test zero usage, empty fields, different volumes and the mobile layout. Confirm the notes explain that licensing, extraction, infrastructure, retries, human review and taxes require separate consideration.
  7. Upload your adapted file to your own GitHub Pages publishing folder. Add a link to it from your website and test the live version.

What I learned

The calculation was only part of the task. Visitors also needed context, transparent assumptions, a practical example and navigation that made a long page manageable.
